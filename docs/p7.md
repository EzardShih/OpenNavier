# P7 Development Order

P7 expands OpenNavier beyond CFD by adding the first capability-gated structure
and thermal workflows. The goal is not broad FEA coverage; it is a small,
verified set of non-CFD cases that prove the multi-solver OS architecture.

Start P7 only after capability registry, ontology, and adapter SDK contracts are
stable enough to reject unsupported structural and thermal requests clearly.

## Domain Position

P7 makes OpenNavier a CAE workbench rather than only an OpenFOAM assistant. It
still follows the same rule as CFD: no capability becomes executable until it
has typed specs, deterministic writers, validators, benchmarks, diagnostics,
and reports.

Water-dam structural workflows are useful examples for future verticals, but
they must remain capability-gated and should not be described as generally
supported by default.

## Development Order

### 1. Linear Elastic FEA Slice

Add the first simple structural mechanics capability.

Target behavior:

- Support a limited linear elastic solid workflow with explicit geometry,
  material, constraints, loads, mesh intent, solver adapter, and result metrics.
- Produce displacement, stress, reaction-force, and safety-summary artifacts
  when supported by the selected adapter.
- Reject nonlinear material behavior, contact, fracture, buckling, dynamics,
  and ambiguous load cases until separate capabilities exist.

Suggested implementation area:

- Core structure spec extensions.
- Future FEA adapter package selected through P6.

Acceptance signal:

- Tests cover valid simple static cases, missing material properties, invalid
  supports, unsupported nonlinear requests, adapter mapping, and report metrics.

### 2. Thermal Conduction Slice

Add the first heat-transfer capability.

Target behavior:

- Support steady conduction or simple conjugate handoff only when geometry,
  material, heat sources, boundary temperatures, heat fluxes, and output metrics
  are explicit.
- Produce temperature, heat flux, energy balance, and thermal report artifacts.
- Reject phase change, radiation, electronics package libraries, and coupled
  CFD-thermal execution until separate capabilities exist.

Suggested implementation area:

- Core thermal spec extensions.
- Adapter package selected through P6.

Acceptance signal:

- Tests cover required thermal properties, unit consistency, boundary families,
  analytical sanity checks, unsupported physics, and report output.

### 3. Thermo-Mechanical Handoff

Plan the first staged coupling between thermal and structural results.

Target behavior:

- Use a completed thermal result as an explicit input artifact to a structural
  run.
- Preserve units, interpolation assumptions, source artifacts, and approvals.
- Mark the workflow as staged coupling, not full multiphysics co-simulation.
- Require separate validation for thermal and structural stages.

Suggested implementation area:

- Core workflow graph models after P10 design starts.
- Interim package APIs for artifact handoff.

Acceptance signal:

- Tests cover valid handoff metadata, missing source artifacts, unit mismatch,
  stale result detection, and report limitations.

### 4. Dam Workflow Draft Capability

Document a future water-dam structural path without marking it executable.

Target behavior:

- Represent a simple 2D gravity-dam static load workflow as a draft capability.
- List required assumptions, hydrostatic loading checks, structural solver
  needs, benchmarks, and unsupported conditions.
- Reject FSI, seismic loading, seepage, uplift, nonlinear foundation behavior,
  and certification-grade conclusions until dedicated capabilities exist.

Suggested implementation area:

- Draft capability manifest examples.
- Documentation under examples or domain notes.

Acceptance signal:

- Tests verify the draft capability cannot be planned as executable and returns
  clear limitations and required next work.

## P7 Completion Gate

P7 is complete only when:

- At least one simple structural and one simple thermal workflow are described
  through capability manifests and ontology-backed specs.
- Unsupported structural and thermal requests are rejected with clear typed
  reasons.
- Benchmarks or analytical sanity checks exist before any workflow is
  executable.
- Water-dam workflows remain draft or explicitly scoped capabilities.
- Focused tests and the full available suite pass.
